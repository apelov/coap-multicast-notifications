# Plan: CoAP Multicast Observe Implementation in C (Standard Libraries)

This plan outlines the design and implementation of a runnable, documented, and maintainable C codebase for the CoAP Multicast Observe mechanism. The design is based on the IETF draft `draft-ietf-core-observe-multicast-notifications` and ensures interoperability with the Java reference implementation from the `californium-thesis-work` (`multicast-notifications` branch) repository.

## 1. Goal & Scope

### Goals
- **Java Reference Interoperability**: Match the CBOR serialization, CoAP message formats, and protocol flow of the Java reference implementation.
  - Specifically interoperate with `MulticastObserveClient` and `MulticastObservableResource` from the Java codebase.
- **Protocol Flow**:
  1. Client sends a unicast CoAP GET request to server with `Observe = 0`.
  2. Server responds with a unicast `5.03 Service Unavailable` response containing a CBOR-encoded `tp_info` payload.
  3. Client decodes `tp_info` (multicast IP, port, group Token) using `libcbor` and joins the multicast group.
  4. Server periodically broadcasts NON (Non-confirmable) multicast CoAP notifications with the group Token and an incrementing Observe sequence number.
  5. Multiple clients receive the multicast notifications and match them using the group Token.
- **Security Support**:
  - Implement unicast security using **standard OSCORE** via `libcoap` (`coap_new_oscore_conf()`).
  - Discuss the limitations of standard C libraries regarding Group OSCORE (which is not natively supported by `libcoap` for multicast contexts) and how the C implementation compares to the Java codebase.

---

## 2. Comparison: Draft vs. Java vs. C

| Protocol Aspect | IETF Draft Specification | Java Reference Implementation | Proposed C Implementation |
| :--- | :--- | :--- | :--- |
| **Transport Info (`tp_info`)** | CBOR map containing `tp_info` array. Host in CRI is text/byte representation of address. | Serializes host as a CBOR **byte string** (`bstr`) of the raw IP bytes (e.g. 4 bytes for IPv4). Omit port if it is default (5683). | Matches Java exactly: serializes IP address as a `bstr` (4 bytes for IPv4) and omits default port to ensure binary interoperability. |
| **Informative Response Code** | 5.03 Service Unavailable. | 5.03 Service Unavailable. | 5.03 Service Unavailable. |
| **Unicast Observe Option** | Observe option MUST NOT be present in 5.03 response. | Removes Observe option from 5.03 response. | Omit Observe option in 5.03 response. |
| **Unicast Security** | Standard OSCORE. | Standard OSCORE. | Standard OSCORE via `libcoap` (`coap_new_oscore_conf`). |
| **Multicast Security** | Group OSCORE. | Custom Group OSCORE implementation. | Sent as plain CoAP (due to native `libcoap` Group OSCORE limitations), with a modular interface layout for payload encryption if needed. |

## 3. Architecture & Detailed CBOR Encoding

### CBOR tp_info Structure
We must match the Java reference implementation's CBOR encoding exactly:
```cbor
{
  0 (tp_info): [
    [ -1 (coap), [ h'7F000001' ] ],                     // tpi_server: 127.0.0.1 (default port 5683 omitted)
    [ -1 (coap), [ h'E00001BB', 56830 ] ],              // tpi_client: 224.0.1.187 (non-default port 56830 included)
    h'11223344'                                         // tpi_token: group Token
  ]
}
```


## 4. Risks & Mitigations

- **Binary CBOR Mismatches**: If host is encoded as a text string instead of a byte string of the raw IP address, the Java client/server will fail to parse it. We will strictly use `cbor_build_bytestring` with the 4-byte IPv4 representation.
- **Multicast Loopback on macOS**: macOS local multicast routing can be tricky. We will set the `IP_MULTICAST_LOOP` option on all client and server sockets.

---

## 5. Acceptance Criteria

1. **Clean Compile**: Builds without warnings using `clang` and standard libraries.
2. **Binary Interoperability**:
   - The C server can generate a `tp_info` payload that matches Java's parsing criteria.
   - The C client can parse `tp_info` payloads generated by the Java server.
3. **Multicast Notification Delivery**: Multiple C clients can run simultaneously, register, join the multicast group, and print the notifications in real-time.
4. **Wireshark Capture**: Standard CoAP packets are captured and dissected by Wireshark.
